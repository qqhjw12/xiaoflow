# 小流 XiaoFlow — 产品设计方案

> 版本：v0.1（原型）｜ 日期：2026-10-23
> 依据：《GitHub 个性化工作流项目调研报告》七大借鉴点设计

## 一、产品定位

**一句话**：给普通人用的个性化工作流工具——把重复的事交给"小流"，把时间还给自己。

| 维度 | 定义 |
|---|---|
| 目标用户 | 不会编程、不想配 API key、不想部署服务器的普通人 |
| 核心价值 | 用"说人话"的方式，把日常生活里的重复事务自动化 |
| 差异化 | 对标 n8n/Activepieces 的极客向：砍掉集成复杂度，保留画布交互、模板、AI 创建 |
| 隐私立场 | 本地优先：数据只存在自己电脑，可随时导出 |

## 二、目标用户场景（原型验证）

- "每天早上想知道天气，别让我自己查"
- "看新闻太费时间，帮我摘要几条"
- "老是忘记喝水、久坐，定时提醒我"
- "生日纪念日太多，提前提醒我准备礼物"
- "每周五把这一周收藏的文章整理成笔记"

## 三、设计原则（从调研提炼）

1. 模板优先：首屏即模板库，拒绝空白画布
2. 说人话：节点叫"当…的时候 / 就帮我…"，不用技术术语
3. 一键试运行：立刻看到结果，不需要任何配置
4. 自然语言创建：会打字就会做工作流
5. 本地优先：localStorage 存储 + JSON 导入导出
6. 小助手人格化：每个工作流是一个"小助手"

## 四、功能架构

```
小流 XiaoFlow
├── 首页（模板库 + 我的工作流）
│   ├── 模板卡片：一键"用这个模板"→ 直接进入编辑器
│   └── 我的工作流：本地保存列表，新建/打开/删除/导出
├── 编辑器（三栏工作台）
│   ├── 左栏：节点库（当…的时候 / 如果… / 就帮我… / AI 帮手）
│   ├── 中栏：画布（拖拽节点、拉线连接、平移缩放）
│   └── 右栏：属性面板（选中节点后配置参数）
├── AI 助手（弹层）
│   └── 输入大白话 → 解析生成工作流 → 落入画布
├── 试运行（弹层）
│   └── 按连线顺序模拟执行，逐步展示每步输入/输出
└── 导入导出（JSON 文件）
```

## 五、节点模型（生活化命名）

| 分类 | 节点 | 对用户展示的名字 | 参数 |
|---|---|---|---|
| 触发器 | `manual` | 我点一下就跑 | — |
| 触发器 | `timer` | 当到了某个时间 | 每天/每周几 + 时刻 |
| 触发器 | `rss` | 当订阅源更新时 | 订阅地址、条数 |
| 触发器 | `weather` | 当天气变化时 | 城市、早/晚 |
| 条件 | `condition` | 如果…就… | 字段、比较符、值 |
| 条件 | `delay` | 先等一会儿 | 分钟数 |
| 动作 | `notify` | 提醒我 | 提醒内容 |
| 动作 | `summary` | 帮我总结一下 | 总结长度 |
| 动作 | `save` | 存到我的笔记本 | 笔记本名 |
| 动作 | `openlink` | 帮我打开网页 | 网址 |
| AI | `aichat` | 问问 AI | 问题 |

数据沿连线流动：每个节点收到上游输出 → 处理后产出自己的输出 → 传给下游。

## 六、交互细节

- **画布**：节点可拖拽；从右侧圆点拉线到另一个节点左侧圆点完成连接；
  空白处拖动平移；Ctrl+滚轮或按钮缩放；选中节点后 Delete 删除
- **试运行**：从触发器开始按连线拓扑序执行；每步 400ms 左右的拟真延迟；
  日志显示「第 N 步 · 节点名 · 输入 → 输出」；遇条件分支展示走哪条路
- **AI 助手**：关键词 + 时间表达式解析（如"每天早上八点""每周五下午三点"），
  自动匹配节点并连线；解析结果用清单告诉用户"我帮你做了什么"
- **持久化**：编辑自动保存到 localStorage；顶部显示"已自动保存 HH:MM"

## 七、技术选型

| 决策 | 选择 | 理由 |
|---|---|---|
| 运行形态 | 零依赖单页 Web 应用（HTML+CSS+原生 JS） | 双击 index.html 即用，无构建、无安装，最适合普通人 |
| 画布 | 原生 SVG + 绝对定位 DOM 节点 | 无框架依赖；后续可平滑迁移到 React Flow |
| 存储 | localStorage + JSON 导入导出 | 本地优先、无后端 |
| AI 创建 | 规则解析引擎（原型期） | 无 API key 也能演示；路线图接真实 LLM |
| 数据 | 模拟数据（标注演示模式） | 原型期验证交互，不接真实服务 |

## 八、路线图

- **v0.1**：模板库 + 可视化编辑器 + AI 解析 + 试运行 + 本地存储 ✅
- **v0.2**：三大生活场景（周报流水线 / 碎片整理箱 / 决策参谋）+ 收集箱随手输入 + 学习成本阶梯指引 ✅
- **v0.3**：真实能力——系统通知、正式运行（常驻定时触发）、可选接入本机 Ollama、收集箱读入本地文件 ✅
- **v0.4（当前）**：手机随时扔——本机投递服务 + 手机网页 + 系统分享直达；开源上线 ✅
- **v0.5**：Tauri/Electron 桌面版（关掉浏览器也能常驻、托盘运行、全局快捷键唤起投递窗）；RSS 真实抓取
- **v1.0**：模板社区分享（导出/导入码）、移动端适配

## 九、v0.2 深化：三大生活场景 + 学习成本阶梯（2026-10-23）

基于真实使用思路的深化方向：**普通人不需要纠结哪个工具最强，只需要知道自己愿意付出多少学习成本。**

### 9.1 学习成本阶梯（产品理念）

首页新增「按学习成本选路线」板块，产品不自我神化，坦诚给出选路建议：

| 站点 | 愿意付出的学习成本 | 推荐 |
|---|---|---|
| 第 1 站 | 零安装零配置，先看到东西跑起来 | 小流自己（模板改改、说句话就生成） |
| 第 2 站 | 稍微学一点，要连接多个外部工具 | Make（新手友好）/ n8n（硬核、可自托管、上限高） |
| 第 3 站 | 完全不想碰技术，要发布到微信/飞书 | 扣子 Coze（注册即用，代价是灵活性与生态绑定） |
| 支线 | 整理自己的文档/笔记 | Obsidian + AI 助手（比一上来就 Dify 务实） |

### 9.2 三大深度场景

**① 职场周报流水线**（tpl-weekly，双链条工作流）
- 链条 A（平时）：📮 我随手一扔 → 🗂️ AI 按「本周产出/遇到的问题/下周计划」归拢 → 📒 存档
- 链条 B（周五）：⏰ 每周五 17:00 → 🗂️ AI 生成周报初稿 → 🔔 提醒审阅
- 人的角色：只做删减和判断。这是「AI 用得好」和「AI 只是聊天」最实的差距

**② 碎片信息整理箱**（tpl-notes）
- 📮 固定入口随手扔（链接/截图/灵感）→ 🗂️ AI 分类、提炼要点、标记"可以用在哪" → 📒 存入笔记
- 核心原则：一次输入，自动分流，人只管扔

**③ 每天帮我选一个**（tpl-decide）
- ⏰ 每天定时 → 🗂️ AI 基于固定约束条件（天气/日程/预算）给 2-3 个选项 → 🔔 提醒选一个
- 价值不在酷，在把决策精力省下来留给重要的事

### 9.3 配套节点与交互

- 新增触发器「📮 我随手一扔」：试运行时弹出输入框，用户扔什么，工作流就处理什么
- 新增 AI 节点「🗂️ AI 帮我整理」：四种预设（周报归拢/周报初稿/碎片整理/决策参谋）+ 自定义提示词
- 执行器改为**逐链执行**：多链条工作流的步骤按链分组展示，不再交错
- AI 解析器新增三类句式识别（周报/碎片/决策），周报场景自动生成双链条结构

## 十、v0.3 深化：从"演示"到"日常真的能用"（2026-10-23）

设计主线：**渐进真实**——每加一层真实能力都不提高门槛：没开通知、没装 Ollama，一切照常可用。

### 10.1 四个真实能力

| 能力 | 实现 | 不可用时 |
|---|---|---|
| 🔔 真通知 | `js/notify.js`：Notification API，需用户点「开启通知」授权 | 自动回退页面 toast，标题闪动，不报错 |
| ⏱ 正式运行 | `js/scheduler.js`：每秒 tick，按 timer 节点真实触发；lastFired 持久化防重复 | 需要页面常开（网页原型边界，桌面版解决） |
| 🤖 本机 AI | `js/ollama.js`：设置里配地址/模型，`/api/tags` 探测可达后，aichat/organize 改走真实生成 | 默认关闭 + 探测失败/生成失败均回退内置模拟回答 |
| 📎 文件投放 | 试运行收集箱支持读入 .txt/.md | 始终可用，纯本地 FileReader |

### 10.2 调度规则（scheduler.nextFire）

- **每天 H:M**：今天已过点且本周期没跑过 → 立即触发一次（补跑）；已跑过 → 明天
- **每周几 H:M**：落到最近的该 weekday H:M；本周期已跑过 → 下周
- **每隔 N 分钟**：从 lastFired 起算；页面关闭超过一个间隔 → 重开立即补一次
- 触发即写 lastFired 并持久化，刷新页面不重复触发同一周期

### 10.3 已知边界（诚实清单）

- 正式运行要求页面保持打开——这是网页原型的硬边界，v0.5 桌面版（Tauri）解决
- 微信/飞书等入口无个人开放 API，不做第三方机器人方案；"随手扔"当前形态为本地收集箱
- 从 file:// 页面连 Ollama 可能受浏览器跨域策略限制，设置弹层内已给出 `OLLAMA_ORIGINS=*` 的解决办法

## 十一、v0.4 深化：手机"随时扔"（2026-10-23）

目标：让收集箱突破"坐在电脑前"的限制。**约束：不碰任何平台私有 API**
（微信无个人开放 API，第三方机器人/破解方案一律不做）。

### 11.1 方案：本机投递服务 + 系统级分享

```
手机（微信/浏览器/任意 App）
   │  ① 手机网页输入           ② 系统共享 → 快捷指令 POST
   ▼
tools/inbox-server.js（零依赖 Node 服务，仅监听局域网）
   │  data/inbox.json（追加，本地私有）
   ▼
小流「📬 投递箱」面板 → 「↘ 带入试运行」→ 收集箱工作流处理
```

两个入口都是**操作系统级能力**：浏览器访问局域网、系统共享菜单。
快捷指令（iOS）/ Tasker（安卓）把"分享"变成一个 POST——微信里长按消息→共享→扔进小流，
全程不经过微信接口，内容直达用户自己的电脑。

### 11.2 关键设计决策

| 决策 | 理由 |
|---|---|
| 独立 Node 服务而非塞进单页应用 | 小流保持"双击即用"零门槛；服务是可选增强，不开也完全可用 |
| GET /drop + POST /api/drop 双端点 | iOS 快捷指令用 POST+JSON 最稳；安卓/极简场景用 GET 带参 |
| 响应带 `Access-Control-Allow-Origin: *` | file:// 页面（origin 为 null）也能直接读投递内容 |
| 端口可配（默认 8787，设置里改） | 端口冲突时换端口即可，小流侧同步 |
| 带入即消费（清空服务端） | 收件箱语义：内容已进工作流，不重复处理 |
| `data/` 加入 .gitignore | 投递内容是用户隐私数据，绝不出现在开源仓库里 |

### 11.3 验证

- 86 项断言（含真实起服务测 drop/get/clear/404/CORS/持久化）
- 无头浏览器实测：投递箱面板正确显示两条手机投递（含来源标签）；手机网页 390px 视口渲染正常

## 十二、v0.4.1 深化：移动端适配 + iframe 删除修复（2026-10-23）

### 12.1 移动端适配

目标：手机/平板连同一 WiFi 就能用小流，而不是"桌面专属"。

- **`tools/serve.js`**：零依赖静态服务器，自动探测局域网 IP 并打印手机该访问的地址；防目录穿越；端口可换
- **布局**（≤640px 断点）：
  - 首页：模板/流程/阶梯卡片全部单列，顶栏紧凑（品牌只留 Logo）
  - 编辑器：工具栏自动换行；**节点库与属性面板改为底部抽屉**（工具栏「🧰 节点」「⚙️ 属性」唤起，点画布空白收起，顶部抓手暗示下滑关闭）
  - 弹层全屏化（bottom sheet 形态），适配单手操作
- **触屏**：画布 `.xf-viewport` 已有 `touch-action: none`，拖节点/拉线/双指缩放与桌面 pointer 事件体系天然兼容，无需额外代码
- **投递箱主机自动判断**：`js/inbox.js` 不再硬编码 `127.0.0.1`——从 http(s) 页面访问时（手机开的 192.168.x.x）自动用当前页面主机名连电脑投递服务；file:// 仍走 127.0.0.1；设置里可显式覆盖

### 12.2 iframe 删除修复（bug）

**现象**：用户在 IDE 预览面板（沙箱 iframe）里点"删除"无反应。
**根因**：确认框用浏览器原生 `confirm()`，沙箱 iframe 无 `allow-modals` 时被静默禁用，代码走不到删除分支。
**修复**：自定义确认弹层 `confirmDelete()`（图标/名称/备份提醒/取消/确认删除），全环境可用且视觉统一；`store.get(id)` 为空时友好提示。
**教训**：本项目常在预览面板 iframe 中使用，**禁用一切原生 alert/confirm/prompt**。
