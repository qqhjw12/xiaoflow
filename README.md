# 小流 XiaoFlow 💧

> 给每个人的个性化工作流 —— 不会编程，也能把重复的事自动跑起来。

借鉴 GitHub 上 n8n（208k⭐）、huginn（50k⭐）、activepieces（25k⭐）、node-red（23.8k⭐）、
automatisch（14k⭐）等优秀开源项目的设计，**面向普通人**重新打造的个人工作流工具。

调研报告与借鉴点分析见 [`docs/github-research.md`](docs/github-research.md)，
产品设计方案见 [`docs/design.md`](docs/design.md)。

## 快速开始

**零安装、零依赖、零构建** —— 双击 `index.html` 就能用（推荐 Edge / Chrome）。

```bash
# 克隆到本地
git clone https://github.com/qqhjw12/xiaoflow.git
cd xiaoflow

# 或用本地服务器打开（体验更佳，避开个别浏览器的 file:// 限制）
python -m http.server 8000
# 浏览器访问 http://localhost:8000
```

## 📱 手机 / 平板也能用

小流做了完整的移动端适配。手机与电脑**连同一个 WiFi**，然后：

```bash
# 1. 在项目目录启动服务（自动探测并打印手机该访问的地址）
node tools/serve.js            # 默认 8000 端口
node tools/serve.js 8080       # 端口被占用就换一个

# 2. 终端会打印类似：
#    💻 电脑打开：  http://localhost:8000
#    📱 手机打开：  http://192.168.0.102:8000    ← 手机浏览器开这个

# 3. 手机浏览器输入上面的地址即可
```

**手机上能做什么**：

| 能力 | 状态 |
|---|---|
| 浏览模板库、一键使用 | ✅ |
| AI 助手说句话生成工作流 | ✅ |
| 画布拖节点、拉连线、双指缩放 | ✅（触屏优化） |
| 试运行、查看每步输入输出 | ✅ |
| 节点库 / 属性面板 | ✅ 底部抽屉，点工具栏「🧰 节点」「⚙️ 属性」 |
| 投递箱（手机扔的内容） | ✅ 自动连到电脑，无需配置 |
| 正式运行（常驻定时触发） | ⚠️ 需手机页面保持打开 |

**说明**：
- 手机访问时数据存在**手机浏览器**里（按网站来源隔离），与电脑端 file:// 打开的数据互不相通——各端独立，可用「导出/导入」在两端搬数据
- 手机端投递箱会自动连接电脑上的投递服务（读取当前页面的 IP），无需手动填地址
- 防火墙如果拦截，允许 Node 通过专用网络即可；服务仅监听局域网，不对外

## 三大深度场景（v0.2 新增）

1. **📋 职场周报流水线**：平时随手扔记录 → AI 按「本周产出 / 遇到的问题 / 下周计划」归拢存档 → 周五自动生成周报初稿，你只管删减和判断
2. **🗂️ 碎片信息整理箱**：链接、截图、灵感都往收集箱扔 → AI 自动分类、提炼要点、标记"可以用在哪" → 存入笔记。一次输入，自动分流
3. **🎯 每天帮我选一个**：把约束条件（天气、日程、预算）固定成提示词 → 每天早上 AI 给 2-3 个选项，你只负责选。把决策精力省给重要的事

## v0.3 真实能力使用说明

**🔔 开启系统通知**：打开任意工作流 → 点编辑器右上角「🔔 开启通知」→ 浏览器弹窗点允许。
之后试运行或正式运行的"提醒我"节点都会弹真通知（浏览器不支持时自动回退成页面提示，不报错）。

**⏱ 正式运行（常驻触发）**：编辑器顶栏点「正式运行」开关即可开启。规则：

- 需要工作流里至少有「⏰ 当到了某个时间」节点（每天 / 每周几 / 每隔一段时间）
- **保持页面打开**才会触发（浏览器标签页关掉就停，这是网页原型的边界）
- 支持"每天 / 每周几"错过时间点后补跑一次（每个自然周期只补一次，不会重复轰炸）
- "每隔一段时间"按上次触发时刻起算：页面关了 2 小时再打开，会立即补一次
- 每次触发都记入「📋 运行记录」（首页或设置里可看，本机保存最多 50 条）

**🤖 接入本机 Ollama（可选）**：

```bash
# 1. 安装 Ollama 后拉一个模型（首次约几分钟）
ollama run qwen2.5:3b
# 2. 若从网页连不上，用允许跨域的方式重启：
OLLAMA_ORIGINS=* ollama serve
```

然后在编辑器「⚙ 设置」里勾选"启用本机 Ollama"、点「🔍 测一下连通性」显示 ✓ 即可。
没装 Ollama 也完全不影响——AI 节点自动用内置模拟回答。

## 📱 手机随时扔（v0.4 新增）

收集箱不该只在你坐在电脑前才能用。小流附带一个**零依赖投递服务**，让手机扔的内容直达电脑收集箱——
全程只用系统级能力，**不碰微信/任何平台的私有 API**。

### 第一步：在电脑上启动服务

```bash
cd xiaoflow
node tools/inbox-server.js          # 默认端口 8787，可换：node tools/inbox-server.js 9000
```

启动后会打印本机地址和手机地址，保持这个窗口开着（内容只进你自己电脑的 `data/inbox.json`）。

### 第二步：手机连同一 WiFi，二选一

**方式 A · 手机网页**：浏览器打开服务打印的地址（如 `http://192.168.1.5:8787`），
一个大输入框 + 一个大按钮，写完即扔，显示"今天第 N 条"。

**方式 B · 系统分享直达（推荐）**：在任何 App 里长按内容 → 共享 → 小流的快捷指令。
配置一次，以后在微信里看到想留的文章，**长按 → 共享 → 扔进小流**，两步到位。

<details>
<summary>🍎 iPhone 配置快捷指令（约 1 分钟）</summary>

1. 打开「快捷指令」App → 右上角 **+** 新建
2. 点「添加操作」，搜索并添加 **「获取 URL 内容」**
3. 展开该操作，按下图设置：
   - URL：`http://192.168.1.5:8787/api/drop`（换成你电脑的 IP 和端口）
   - 方法：**POST**
   - 头部：添加 `Content-Type` = `application/json`
   - 请求体：选 **JSON**，添加一个文本字段：
     - 键 `text`，值选变量 **「共享输入」**（Shortcut Input）
     - 键 `source`，值 `ios-shortcut`
4. 点顶部名字，重命名为「扔进小流」，完成
5. （重要）底部「共享表单」设置里，勾选接收「文本」和「URL」

之后：微信里长按消息 → **共享** → 「扔进小流」，内容就进了电脑的收集箱。
</details>

<details>
<summary>🤖 Android 配置（两种）</summary>

- **Tasker / MacroDroid**：新建任务 → 「HTTP 请求」POST `http://电脑IP:8787/api/drop`，
  请求体 `{"text":"%CLIPBOARD 或分享文本","source":"share"}`，触发器选"分享文本到本任务"
- **不装 App 的极简法**：用系统分享菜单里的浏览器打开 + 书签脚本，
  或直接把内容发到自己的微信，回到电脑前粘贴进小流试运行框（也支持拖入 .txt/.md）
</details>

### 第三步：在小流里消费

编辑器顶栏「📬 投递箱」→ 看到手机扔进来的 N 条（带来源和时间）→
点「↘ 带入试运行」→ 直接点「▶ 试运行」。碎片整理箱、周报流水线会自动处理这些内容。

> **安全提示**：服务无认证、仅面向家庭/办公网络，不要暴露到公网；
> 换端口启动后，记得在「⚙ 设置」里把投递端口改成同一个。

## 项目结构

```
personalization/
├── index.html            # 入口（双击即用）
├── css/
│   └── style.css         # 样式
├── js/
│   ├── data.js           # 节点定义 + 内置模板 + 模拟数据
│   ├── store.js          # localStorage 存储（含 file:// 降级）
│   ├── notify.js         # 真实系统通知（Notification API + 回退）
│   ├── ollama.js         # 可选接入本机 Ollama（探测/生成/设置）
│   ├── inbox.js          # 投递箱客户端（连本机 inbox-server）
│   ├── scheduler.js      # 正式运行：常驻定时触发 + 运行记录
│   ├── ai.js             # 自然语言 → 工作流 解析引擎
│   ├── runner.js         # 试运行引擎（拓扑执行 + 环路检测 + 异步节点）
│   ├── canvas.js         # 可视化画布（拖拽/连线/缩放）
│   └── app.js            # 主应用（路由/首页/编辑器/弹层）
├── tools/
│   ├── inbox-server.js   # 手机投递服务（node tools/inbox-server.js）
│   └── serve.js          # 静态服务器，手机/平板访问小流用（node tools/serve.js）
└── docs/
    ├── github-research.md  # GitHub 调研报告
    ├── design.md           # 产品设计方案
    └── smoke-test.js       # 逻辑测试（node docs/smoke-test.js）
```

## 路线图

- **v0.1**：模板库 + 可视化编辑器 + AI 解析 + 试运行 + 本地存储 ✅
- **v0.2**：三大生活场景（周报流水线 / 碎片整理箱 / 决策参谋）+ 收集箱随手输入 + 学习成本阶梯指引 ✅
- **v0.3**：真实能力——系统通知、正式运行（常驻定时触发）、可选接入本机 Ollama、收集箱读入本地文件 ✅
- **v0.4**：手机随时扔——本机投递服务 + 手机网页 + 系统分享直达；开源上线 ✅
- **v0.4.1（当前）**：移动端完整适配（手机/平板浏览器可用：底部抽屉、触屏画布、一键起服务）+ 修复删除按钮在 iframe 预览面板失效 ✅
- **v0.5**：Tauri/Electron 桌面版（关掉浏览器也能常驻、托盘运行、全局快捷键唤起投递窗）；RSS 真实抓取
- **v1.0**：模板社区分享

> 关于"微信文件传输助手"入口：微信没有面向个人的开放 API，不做需要第三方机器人或破解的方案。
> "随手扔"的落地形态是本地收集箱（试运行时输入 / 拖入 .txt/.md / 手机投递），完整入口留待桌面版再做。

## 设计原则（来自调研 + 用户实践）

1. 模板优先，而非空白画布
2. 说人话的节点命名
3. 一键试运行 + 看得懂的日志
4. 自然语言创建工作流
5. 本地优先、隐私自持
6. 小助手人格化
7. **按学习成本选路，不比工具强弱**：先跑起来 → 再串工具 → 最后谈发布
8. **渐进真实**：没装 Ollama、没开通知都不报错，能力一层层加，门槛始终是零
